# mref

mref is a small library that takes on some of the functionality that pymel
previously held. Allowing a user to get a reference to a node and interact
with it at a higher level.

Rather than dealing with large hierarchical structures it just binds traits
to the object which then exposes functionality. A mesh shape gets mesh
methods, a joint gets joint methods, a skin cluster gets skinning methods —
and every node still works with plain `maya.cmds`.

```python
import mref
from maya import cmds

node_a = mref.create("transform", name="node_a")
node_b = mref.create("transform", name="node_b", parent=node_a)

# -- We can mix in cmds too - lets use cmds to create a node
# -- and then get the reference to that using mref
node_c = cmds.createNode("transform", name="node_c")
node_c = mref.get(node_c)

# -- Now lets rename them
node_a.rename("foo_a")
node_b.rename("foo_b")
node_c.rename("foo_c")

# -- As we're dealing with a reference we can still interact with
# -- it. Because its a transform, it will have the DAG trait, allowing
# -- us to manage parenting
node_a.add_child(node_b)

# -- Lets add an attribute, and then print the value
node_a.add_attribute(name="my_name", value="bob", attribute_type="string")
print(node_a.attr("my_name").get())

# -- Finally, lets use maya cmds commands with these objects
cmds.parentConstraint(node_c.name(), node_a.name())
```

**Requirements:** Maya 2024 or later (Python 3.10+), plus the `factories`
and `signalling` packages on the Python path. The full test suite passes on
Maya 2025 and 2026.

## API docs

You can view the API Docs from the Github Pages site here: 
https://mikemalinowski.github.io/mref/

Alternatively, open [`docs/index.html`](docs/index.html) in a browser for the full API: a
page for every trait and every Maya node type, listing each method with its
signature, docstring and the trait it comes from. Node type pages show
which traits bind to that type and mark any method a higher priority trait
overrides. The sidebar search covers traits, node types and methods.

The page is generated from the trait source, alongside the typing stubs, so
it is regenerated by the same command — see
[Keeping the stubs up to date](#keeping-the-stubs-up-to-date). To rebuild only
the docs, run `mref.generate_docs()`.

## Getting nodes

```python
import mref
from maya import cmds

# -- Create nodes. Names are made unique unless unique=False, and parent
# -- accepts a ReferencedItem or a name.
rig = mref.create("transform", name="rig_grp")
root = mref.create("joint", name="root", parent=rig)
tip = mref.create("joint", name="tip", parent=root)
tip.set_position([10, 0, 0], space="world")
root.orient_to_child(aim_axis="x", up_axis="y")

# -- Wrap anything that already exists: a name, an MObject, an MPlug or
# -- another ReferencedItem
body = mref.get(cmds.polyCube(name="body")[0])
shape = body.shape()

# -- Searching and selection return a ReferenceList (a list with
# -- .names() / .full_names() helpers)
joints = mref.find("*", type="joint")
mref.select(joints)
print(mref.selected().names())        # ['root', 'tip']

# -- Any maya.cmds command can be called through mref. ReferencedItems are
# -- converted to names on the way in, and returned names come back as
# -- ReferencedItems
target = mref.spaceLocator(name="target")[0]
constraint = mref.parentConstraint(target, body, maintainOffset=True)[0]
print(constraint.drivers().names())   # ['target']
```

`ReferencedItem`s hold the node itself rather than its name, so they keep
working after a rename or reparent.

## Attributes

Attributes are ReferencedItems too, bound to the plug.

```python
# -- Property-style access resolves Maya attribute names...
body.translateX.set(2)
print(body.translateX.get())                 # 2.0

# -- ...and attr() / attribute() do the same by name. attribute() returns
# -- None for a missing attribute rather than raising.
body.attr("rotateY").set(45)
print(body.attribute("doesNotExist"))        # None

# -- Adding and configuring attributes
speed = body.add_attribute(name="speed", value=1.0, attribute_type="float")
speed.set_minimum(0.0)
speed.set_keyable(True)
speed.lock()
speed.unlock()

print(speed.is_dynamic(), speed.minimum(), speed.default_value())
print(body.has_attribute("speed"))
print(body.attributes(userDefined=True).names())

# -- Structure: compounds, arrays and enums
print([child.name() for child in body.translate.children()])   # translateX/Y/Z
print(speed.is_array(), speed.is_compound(), speed.enum_names())
```

## Connections

```python
# -- Connect: the source drives the destination
rig.translate.connect(body.translate)

print(body.translate.is_connected())                         # True
print(body.translate.source().name(include_node=True))       # rig_grp.translate
print([node.name() for node in rig.outputs()])               # ['body']

# -- Plug-level pairs for a whole node, always (source, destination)
for source, destination in body.plug_connections(destination=False):
    print(source.name(include_node=True), "->", destination.name(include_node=True))

# -- Upstream / downstream graph walking
print(shape.history(node_type="geometryFilter"))
print(rig.future())

# -- Disconnect from the source side
rig.translate.disconnect(body.translate)
```

## Deleting

```python
speed.delete()                    # dynamic attributes and array elements
print(body.has_attribute("speed"))     # False

target.delete()
print(target.exists())            # False — the reference knows the node has gone
```

## Working with specific node types

Every node gets the methods of each trait that applies to it, so the same
object exposes generic and specialised behaviour together.

```python
skin = mref.get(cmds.skinCluster(root.full_name(), body.full_name())[0])

print(shape.assigned_traits())    # DependencyNode, MayaObject, DagNode, Shape and Mesh
print(shape.vertex_count())                          # Mesh
print(shape.deformers().names())                     # Shape
print(skin.influence_weights(root))                  # SkinCluster
print(skin.envelope())                               # GeometryFilter (every deformer)

shape.print_methods()             # every method available on this node
```

See the [trait reference](#trait-reference) for what each node type offers.

## Autocomplete and typing

mref ships typing stubs (`mref/types.pyi` and `mref/__init__.pyi`) which give
IDEs autocomplete, signatures and docstrings for every trait method. Each
Maya node type has a class named after it — `mesh` is
`mref.types.MeshNode`, `skinCluster` is `mref.types.SkinClusterNode`, and so
on — and each trait has a `<Name>Trait` class.

### Where autocomplete works on its own

**`mref.create()` with a literal node type** is typed automatically:

```python
joint = mref.create("joint")      # -> mref.types.JointNode
joint.orient_to_child()           # completes, with signature and docstring
joint.get_position(space="world") # -> list[float]
```

**Anything returned from a typed node keeps its type** where the method
declares it — `shape.vertex_positions()` is `list[list[float]]`,
`skin.envelope()` is `float`.

**Maya attributes accessed property-style** are typed as attributes:

```python
joint.translateX.get()            # .get(), .set(), .connect() ... complete
```

`mref.create("<type>")` relies on `Literal` overloads, which PyCharm and
VS Code (Pylance) support. Editors built on jedi do not, and need an
annotation there too.

### Where you must annotate

The node type behind a name is only known once Maya runs, so anything that
looks a node up returns an untyped value. Annotate the variable to get
autocomplete:

```python
shape: mref.types.MeshNode = mref.get("bodyShape")
skin: mref.types.SkinClusterNode = shape.deformers(node_type="skinCluster")[0]
target: mref.types.TransformNode = mref.spaceLocator()[0]
speed: mref.types.Attribute = joint.attr("speed")
```

That applies to:

- `mref.get()`, `mref.find()`, `mref.selected()` and every `maya.cmds`
  command called through mref
- methods which return a node or list of nodes without knowing its type —
  `shape()`, `parent()`, `children()`, `inputs()`, `deformers()` and similar
- `attr()` / `attribute()` (property-style access is already typed)

The annotations are safe at runtime: every name in `mref.types` resolves to
`ReferencedItem` when the code actually runs, so they can be used in
function signatures too.

```python
def mirror_weights(skin: mref.types.SkinClusterNode) -> None:
    ...
```

### Keeping the stubs up to date

The stubs and the [API docs](#api-docs) are generated from the trait source,
so **they must be regenerated whenever you add a trait or add/change methods
on an existing trait** — otherwise your new methods won't autocomplete or
appear in the docs. One command regenerates both. From Maya:

```python
import mref

# -- Added or changed methods on existing traits (about a second)
mref.generate_stubs(probe=False)

# -- Added a new trait, or changed a trait's can_bind (about ten seconds)
mref.generate_stubs()
```

The full form works out which traits bind to every Maya node type by
creating one of each in a separate `mayapy` process, so your open scene is
never touched. Node types from plugins are included if the plugin is loaded
in your session (Arnold, matrixNodes, quatNodes and lookdevKit are always
loaded for it). The output is deterministic, so regenerating only changes
the files when something really changed.

If you forget, `test_stubs` and `test_docs` fail and tell you which command
to run.

## How it works

- **`ReferencedItem`** wraps a Maya handle — an `MObject` for nodes, an
  `MPlug` for attributes.
- **Traits** are classes in `mref/traits/` which subclass `mref.Trait`. The
  `TraitLibrary` discovers them all on first use. When a `ReferencedItem` is
  created, every trait whose `can_bind()` accepts the handle is attached.
  Most traits bind on an OpenMaya function set (`pointer.hasFn(om.MFn.kMesh)`),
  so one trait covers a whole family — `GeometryFilter` binds to every
  deformer.
- **Method lookup** runs through the bound traits highest priority first:

  | Priority | Traits |
  |---|---|
  | `-1` | `DependencyNode` (every node) |
  | `0` | Family traits: `DagNode`, `Transform`, `Shape`, `GeometryFilter`, `ObjectSet`, ... |
  | `1` | Specific traits stacked on a family: `Mesh`, `Joint`, `SkinCluster`, `Camera`, ... |
  | `2` | `SpotLight` (stacked on `Light`) |

  When two traits define the same method, the higher priority wins — that
  is how `DagNode.full_name()` (the DAG path) overrides
  `DependencyNode.full_name()`.
- **Attribute names**: anything that isn't a trait method falls through to
  `DependencyNode.__getattr__`, which resolves Maya attributes —
  `node.translateX`.
- **`maya.cmds` passthrough**: `mref.<command>` that isn't an mref function
  is wrapped from `maya.cmds`, converting arguments and results.
- **Caching**: the trait list is cached when mref first loads. After
  editing traits in a running Maya, reload mref (for example with
  `blackout.drop("mref")`) or restart Maya.

## Extending mref

Add a file to `mref/traits/` containing a class which subclasses
`mref.Trait`. This is the shape of the real `Camera` trait:

```python
import mref
from maya.api import OpenMaya as om


class Camera(mref.Trait):
    """
    Trait bound to any node with ``MFn.kCamera`` ...
    """

    # -- Sits above the generic Shape trait
    priority = 1

    @classmethod
    def can_bind(cls, pointer: om.MObject) -> bool:
        return isinstance(pointer, om.MObject) and pointer.hasFn(om.MFn.kCamera)

    def focal_length(self) -> float:
        """
        Returns the focal length of the camera in millimetres
        """
        ...
```

Rules:

- **Class names must be unique** across `mref/traits` — traits are
  registered by class name.
- **Subclass `mref.Trait` directly, and never import another trait
  module.** Any trait class visible in a module is registered, so imports
  and subclasses register twice.
- **Follow the priority convention** above: `0` for a family trait, `1` for
  a trait stacked on a family.
- **Check method names** against the other traits that bind to the same
  nodes (`node.print_methods()`), and remember that a method name hides any
  Maya attribute of the same name from property-style access —
  `node.attr("name")` still reaches it.
- **Keep `can_bind` cheap** — it runs for every trait on every
  `ReferencedItem`. Prefer `hasFn` checks, and cache anything slower per
  node type.
- **Add a `tests/test_<file>.py`**, and **regenerate the stubs** (see
  [Keeping the stubs up to date](#keeping-the-stubs-up-to-date)).

## Running the tests

```python
import mref
mref.test()                       # everything
mref.test(target="test_mesh")     # one module, class or test
```

Every test starts a new scene, so **save your work first**. The tests also
run headless under `mayapy`.

To pick up changes while iterating in a running Maya:

```python
import blackout
blackout.drop("mref")
from mref import tests
tests.run()
```

## Maya version notes

mref handles these differences itself; they are listed so the behaviour is
not a surprise.

- **Blendshape weights** — up to Maya 2024 painted base weights live in
  `inputTarget[n].baseWeights`; from 2025 they live in `weightList`.
  `deformer_weights()` and `base_weights()` read whichever one the running
  Maya uses.
- **openPBRSurface** only exists from Maya 2026, where it is also the
  default shader.
- **Arnold lights** are not Maya lights as far as the API is concerned, so
  `Light` also matches light shapes by classification.
